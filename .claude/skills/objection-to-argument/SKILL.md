# Objection to Argument

## The output

One argument per objection, each one testable.

## The prompt

```
Below are objections and anxieties, in customers' words.

SOURCE: [PASTE]

Invert each into an ARGUMENT the creative could make. An argument is a claim
that, if believed, removes the objection.

Emit only:

| Objection | The argument that answers it | Proof it needs | Testable in one asset? |

Rules:
- The argument must be a claim, not a reassurance. "It is built to last" is a
  reassurance. "It survives the thing that broke your last one" is a claim.
- Proof it needs: name the specific evidence required. Write NONE REQUIRED only
  if the claim is self evident on camera.
- Testable in one asset: YES or NO. NO usually means the objection is really
  two objections.
```

## Why objections outperform benefits

A benefit competes with every other brand's benefit. An objection is already in
the buyer's head, unresolved, and the ad that resolves it is the only ad in the
feed doing work rather than talking. In most accounts we look at, the highest
performing asset is answering an objection by accident. This makes it deliberate.

## What to do with it

Every row goes to `proof-match` before it can be briefed. Rows that come back
without proof are not dead, they become the questions the brand should be
answering on the product page first.
